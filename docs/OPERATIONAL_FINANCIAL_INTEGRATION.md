## Demonstrated defects and fixes

1. A reimbursement could carry Project A in the document/evidence while settling Project B in the journal. The isolated pre-fix reproduction accepted it. Additive87 guards inserts to the existing canonical financial posting table: personal reimbursement must use the original liability's Company/Project. A mismatch rolls back its document and journal atomically. Existing approval, funds, remaining-liability, request-hash/idempotency and reversal controls remain. The UI filters eligible original liabilities by the reviewed evidence Project and explains missing matches; it never rewrites evidence or invents a Project assignment.
2. Direct Partner handovers reached the Custody GL/reconciliation but were absent from Custody document history. History now includes the existing operational funding document, original source/evidence, current reversal state and journal, explicitly without Treasury transit. Bank receipts addressed to the same recipient are excluded. A direct handover opens its existing financial-evidence workspace; it cannot accidentally call Expense reversal or become an ordinary Custody advance.
3. Contract history omitted canonical advances. It now includes advances as assets alongside certifications/settlements, retaining contract scope and separate outstanding-payable/advance measures.
4. Following86, Treasury gross accounting reversal/replacement could be labelled as new receipts/payments, and contract replacements as actual new payments. Read-only87 correction metadata identifies the committed pair. Treasury splits funding movements excluding reclassification from gross correction debit/credit and retains full GL movements/running balances. Contract measures say active settlements; document rows, Custody history, Project cost references and bilingual exports retain correction/original-payment context. This corrects presentation/traceability, not previously valid journal amounts. These are GL reports, not independently certified bank-statement or physical-cash evidence.

The safe read command accepts at most500 explicit journal IDs per call. Company accounting reader roles and existing payroll-journal visibility are authoritative. Sensitive Employee chains expose only an accounting-only flag for an already visible journal; source/correction/original-payment identities and dates are redacted without payroll permission. Hidden Employee journals remain hidden. Browser table-write grants, tenant/RLS policies, canonical commands and posted journals are unchanged. The guard is a private trigger with fixed empty search path and no browser EXECUTE; the public read helper has fixed empty search path and authenticated-only EXECUTE.
