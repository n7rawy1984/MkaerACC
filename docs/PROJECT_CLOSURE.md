# M3 / PRJ-01 — Controlled administrative Project closure

Implemented 2026-11-04. The existing Project UUID moves COMPLETED → CLOSED only after a fresh supported-scope readiness review, required documented resolutions, explicit responsibility acknowledgment, reason and immediate server-effective date. Operational completion, financial reconciliation and administrative closure remain distinct. No journal, recognition, WIP settlement, cash reversal, retention release or write-off is generated by closure. Existing Planning activation and migration74 operational transitions/history remain intact.

## Readiness and accounting boundary

Readiness derives exact posted Project cost and separate account/Party/Subcontract balances from actual journal dimensions. Complete visible journals and original source references are checked. Operational source/contract/draft counts never enter GL balances. Reversed sources retain actual journals; the closure decision records its original snapshot, while current exposure reports can reflect later authorized settlements/reversals. Unassigned custody returns are not inferred into a Project.

Findings have three classifications:

- **Blocking:** Project not operationally completed; linked unposted Expense evidence/shared allocations; draft certificates; unexecuted latest cost-correction reviews; active Payroll defaults or pending included Payroll allocations; unknown/unmatched posted sources; journal/dimension discrepancies; incomplete or unverifiable contract work; outstanding advances/custody, debit payables or unsupported balances; and bank-linked transactions whose reconciliation cannot be demonstrated. Notes and acknowledgment cannot waive a blocker.
- **Documented resolution required:** complete supported contract closeout and source/settlement/period review. For the current fixed-value Subcontract model, certified gross and cumulative work must both equal the positive revised contract value before an open contract may receive a closeout reference/reason. A status label, zero/unknown cap or incomplete/cancelled scope does not substitute for that proof. There is no automatic contract status/economic amendment. Financial review evidence is an operator reference/reason, not an invented bank reconciliation or external verification flag.
- **Permitted outstanding:** actual credit balances in Supplier payable, Subcontractor payable, held retention and salary payable, separately by account/Party/contract. Their existing specialized settlement commands remain available after closure. They are not required to be paid merely to close the Project administratively.

The accountant must document review of sources, periods and ongoing settlement responsibilities and confirm no unresolved or unknown external issues remain. Unsupported bank cases remain blocked regardless of evidence text. There is no generic draft-journal or purchase-order module in this scope; coverage states that limitation rather than inventing balances or certifying external commitments. Existing scoped correction-period controls remain unchanged; Project closure is not a fiscal close. Pending corrections block even when a required period/policy prevents their resolution. Unknown/unlinked source evidence cannot be assigned from names or guessed into this Project.

Only the existing Accounting administrator with `project.manage`/`payroll.manage` closes Projects, preserving the single-accountant model and prior lifecycle authority. Existing Accountant readers may view/export recorded decisions; reporting viewers and Project managers receive no new financial snapshot or transition authority. Company is validated server-side and every audit query is scoped. Financial snapshots retain the existing Payroll boundary.

## Atomic command and after-closure controls

`preview_project_closure` returns scoped findings, exact dependency snapshot/hash, date and capture time. `close_project` derives and locks current authority, serializes the Company/request key, locks the exact Project version, recomputes readiness and checks the hash, validates a complete normalized set of supported evidence keys, then commits CLOSED plus immutable closure evidence atomically. Reasons/references must be bounded text; arbitrary JSON or unsupported/duplicate resolution keys are rejected. Same-key replay uses its immutable reviewed facts and returns its original receipt even after later settlement; changed intent, stale Project/dependencies and revoked authority fail. Closure is effective today in Asia/Dubai; no backdating, scheduling or closed-Project reopening is introduced.

Six narrow insertion/update guards serialize relevant journal dimensions, Subcontract/certificate commitments, Payroll defaults/explicit accounting allocations and source assignments with closure. A posting that read an older status cannot slip through after closure. Original posting/RLS/authorization/period functions are not rewritten. Closed journal inserts allow only existing specialized settlement types without Expense lines, or their existing authenticated specialized reversal path. New recognition and cost allocation remain blocked. No generic browser journal writer is introduced.

Raw Payroll draft default hints remain source evidence: the guard applies to new active defaults and **explicit financial allocations**, preserving existing Company-wide draft capture. Closure itself blocks active/default or pending attributed Payroll work. Earlier posted records and existing metadata remain visible; descriptors can still be maintained. The guards have no data backfill. Existing legacy Closed Projects retain eligible settlement and salary payment; no automatic reopen occurs. Unsupported advances/custody closeout, bank reconciliation, scope cancellation/amendment and Closed reopening remain separate unfinished workflows.

## Interface and exports

The existing Projects list gains an inline closure review with classified findings, blockers, separately identified obligations, required evidence fields, closure reason/date and explicit confirmation. Missing schema/read access fails closed; session/tenant/version changes discard old results. Uncertain responses retain the same frozen request for retry; known success with failed list refresh retries the read. Closed Projects show the immutable decision and current exposure, with a link to existing accounting reports/source references.

English LTR and Arabic RTL preserve the approved design/five themes. Tables retain readable widths with contained narrow scrolling. Excel/PDF include Company/Project identity, reporting date, classifications, separate liability amounts, contract verification, evidence references, effective closure date, operator, reason and audit ID. Current readiness and original decision snapshots are distinguished. Reports are not fiscal-close certificates or complete financial statements.
