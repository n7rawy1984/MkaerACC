# M3 — Shared cost allocation

Implemented: eligible posted simple cash Expenses can be allocated across up to20 active Company Projects and explicit Company overhead using the existing correction workflow. This completes the next bounded PRJ-02/PRJ-03 increment, not all M3.

Methods: direct assignment to one destination; documented percentages totaling100%; measured quantities; or an explicitly documented indirect driver with units. The accountant records the business basis, supporting reference and approval for consistent application. No driver is inferred. Basis, support, positive weights, distinct destinations, and approval are mandatory. Unsupported/unapproved plans cannot post. Units support six decimal places; percentages use integer basis points.

Rounding: exact integer/numeric arithmetic, whole AED minor units, largest remainder `LARGEST_REMAINDER_V1`. Remaining fils go to descending remainder, with canonical Project UUID order for ties and overhead last. Input reordering cannot change amounts or replay hashes. Zero-minor destinations are rejected for revision. The allocated amounts always equal the original net cost exactly. Money remains BIGINT; no floating-point financial truth is persisted.

Accounting: Dr each destination cost / Cr original cost, using existing PROJECT_COST and COMPANY_EXPENSE mappings. This preserves Company-wide net expense and every original Expense/journal/cash/settlement record. It does not recognize inventory, assets, advances or payments as new expense. Actual Project journal dimensions and dates drive the existing ledger. The review's proposed Project/overhead remains an anchor included in the final plan; `allocation_plan` is the complete authoritative destination snapshot. Execution views/exports identify shared allocation and show every amount rather than presenting that anchor as the whole allocation.

Timing and eligibility inherit migration69: source in the current UTC month, correction dated today, explicitly open scoped correction period, FULL existing access, latest unchanged Project review, active Projects, standard original two-line cash journal, no VAT, party/supplier, bank/Project-restricted Treasury or settlement dependency. Independent proof and an unreconciled/no-contract/no-external-settlement attestation are required. This does not implement general financial closing or permit reopening closed books. Prior-period, bank/reconciled, settled and other uncertain corrections remain blocked.

Integrity: migration70 adds one nullable immutable JSON snapshot column to `project_cost_corrections`, a private exact planner, and one narrowly scoped execution RPC. It reuses the same actor/permission checks, receipts/PCC reference, one-execution-per-review and one-live-correction-per-Expense rule, period controls, source-reversal dependency and exact correction reversal. No competing allocation ledger or system accounts are introduced. The receipt and balanced journal commit atomically. Company/profile/membership/Project/Expense/Treasury/account locks and normalized request hashes preserve isolation, replay and concurrency. Fixed search paths and minimal grants remain; existing RLS/permissions and financial/Auth/subscription function definitions are unchanged. The browser supplies business inputs only. Recorded execution by the authenticated accountant constitutes the approved-basis event; supporting business evidence remains an operator responsibility.

UI: the existing Expense correction panel adds a shared-allocation editor and preview, explicit basis approval and final confirmation. Uncertain responses retain the frozen request. Execution history and the Project-cost ledger show destination amounts and original-to-PCC lineage; the existing correction-only reversal reverses every allocation line and restores original dimensions without reversing cash.
