## Valuation and accounting policy

Approved setup fixes **perpetual moving weighted average per Company/material/location**. Financial amounts persist as BIGINT minor units; quantities persist as BIGINT base micro-units, six decimal places. UOM conversions must be exact at that precision; nonrepresentable quantities are rejected. Account mappings are explicit, separate approved controls, not display-name lookup or arbitrary document inputs. Unused inventory/GRNI/variance/opening controls can be selected or explicitly created by an authorized Admin with supplied codes/names and approval. Setup recognizes no stock and cannot silently absorb an existing asset balance.

Weighted-average is an established cost formula: [IFRS Foundation, IAS2](https://www.ifrs.org/issued-standards/list-of-standards/ias-2-inventories/). Location scope, the V1 supported document set and current-period cutover boundaries are explicit product policies. This implementation is a supported cost subledger; it does not claim complete IAS2 measurement/disclosure, NRV assessment, financial statements or jurisdictional tax certification.

A 100-bag receiving at AED25 creates100 bags/AED2,500 Inventory. An issue of40 bags creates AED1,000 Project cost, leaving60 bags/AED1,500. Bank/Cash/Custody is unchanged by receipt and consumption. Invoice matching and subsequent existing Supplier payment are separate; canonical tax remains on the original invoice. One document currently contains one material/location event; an existing Expense is capitalized/matched as a whole exact net cost, not partially or across multiple materials.

Issue/transfer valuations use current source average and final residual carrying value. Returns use cumulative original issue cost; repeated tiny returns cannot exceed its original value through rounding. Transfers carry cost without a second purchase. Posted document corrections append exact stock and canonical journal reversals. Later active movements/returns/adjustments/matches must unwind first; reversed later movements do not permanently trap earlier documents. New accrued-receipt invoices post through the existing Supplier invoice command and match within the same transaction. Unpaid invoice correction reverses matching and the canonical invoice/VAT atomically; paid-invoice dependencies reject and roll back the entire correction. Canonical invoice/reversal references appear in the UI/audit exports. Existing Expense reversal/reclassification/allocation cannot bypass a live inventory capitalization. Inventory value must equal the actual configured inventory GL balance at each command commit and read; failed reconciliation rolls back/fails closed.

## Historical purchases and supported boundaries

Purchase-history links reference existing Company source/Expense IDs and preserve the raw source, amount/date, attachments and audit; they reimport nothing and create no quantity, value, cash, liability or cost. An invoice is never proof that all its materials remain in stock. Source-linked receiving/matching also creates immutable FK-protected purchase references. Unverified or ineligible historical invoices remain references. Explicit receiving evidence and independently supported valuation are required before stock recognition.

Eligible existing-cost capitalization/matching requires current-period, chronologically valid, posted, unsplit, exact-net Expense recognition without an existing allocation/reclassification. Existing canonical invoice Input VAT is preserved; the stock command neither computes nor changes tax. Prior-period, partial/multi-material invoice capitalization, already-corrected sources, supplier returns/credit notes, landed-cost allocation, serial/batch/expiry tracking, reservations, negative stock, alternative cost formulas, sales/production/WIP integration and value-only NRV/write-down workflows are not silently approximated. They remain advanced commercial requirements/policy gates. Opening stock whose cost/asset was already recognized requires its own supported correction/cutover policy and is blocked here.

Stock dates must satisfy existing explicitly OPEN current-period controls and chronological valuation. Historical/closed-period backdating is unsupported. Closed-Project cost changes remain subject to the existing kernel; no frozen invariant or financial period is reopened. Administrative Project closure protects remaining site stock; transfers do not invent Project cost. Read access remains Company/role scoped; no System Admin financial bypass. V1 uses a complete Company snapshot and Company-level financial/stock serialization; high-volume pagination/performance remains a commercial/operations concern rather than new infrastructure in this slice.
