# M3 / PRJ-01 — Controlled Project lifecycle

Implemented 2026-11-04: ACTIVE → ON_HOLD, ON_HOLD → ACTIVE, ACTIVE → COMPLETED and COMPLETED → ACTIVE. These are immediate operational transitions, authorized for the existing Accounting administrator with `project.manage`, using the same Company Project UUID. Existing Planning → Active activation and its independent audit are unchanged. ON_HOLD → COMPLETED is not introduced: resume before completing. CLOSED is not reachable through the new command and CLOSED → ACTIVE remains unavailable.

Hold/completion are not financial freezes or financial-period closing. Existing financial commands retain their existing recognition/settlement/correction eligibility. Administrative transitions produce no journal, cost, revenue, WIP recognition, cash reversal or retention release. Reopening Completed restores operational Active status only; it does not reopen a fiscal period. This bounded scope follows the requested independent lifecycle capability without inventing unsupported accounting policy.

## Review and command

The existing Projects screen gains an inline lifecycle control with requested status, server-derived effective date, mandatory reason, reviewed dependency disclosure, explicit acknowledgment and confirmation. Effective date is today in Asia/Dubai and changes apply immediately. Backdating/scheduling is unavailable; request replays still recover their original receipt after its original date. No financial/execution date or historical status backfill is inferred.

The server previews linked unposted Expense sources (including confirmed shared allocations and explicit legacy completion mappings), non-closed Subcontracts, draft certificates, pending latest correction reviews, historically split Expenses, exact posted Project cost debit/credit/net, and separate nonzero Party-required balance-sheet balances by actual Project/GL account/Party/Subcontract. Payable, advance and retention balances never combine. Journal dimensions are authoritative; unassigned custody returns are not guessed into the Project. Unmapped/unlinked source evidence and unconfirmed in-browser allocation drafts cannot be assigned by inference. Dependency counts are operational, not posted amounts. A zero scoped GL group is not proof that every Company/contract obligation has cleared.

Preview includes a deterministic dependency hash. Confirmation derives the actor, locks Company/profile/membership authority, serializes the request key and locks the exact Project version; it rechecks dependencies and permits only the specified state pairs. Normalized actor/intent hashing makes same-key retry safe, rejects changed intent and commits status plus immutable event atomically. Changed Project metadata or dependency review requires refresh. Unrelated legacy metadata normalization rolls back. Existing direct browser status writes remain denied. The event retains previous/new status, effective/recorded dates, reason, operator UUID, review snapshot/hash, request and exact versions.

Outstanding obligations are disclosed and explicitly acknowledged; operational completion does not declare them extinguished and does not trap settlement. Closure returns `CLOSURE_POLICY_UNAVAILABLE` even for an apparently empty Project.
