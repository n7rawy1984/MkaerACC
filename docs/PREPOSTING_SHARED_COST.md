# M3 — Pre-posting shared-cost integration

Implemented on 2026-11-04: the existing Expenses source review/posting workflow now confirms a shared-cost plan before recognizing an eligible cash Expense. It reuses migration70's exact plan representation, methods, documented basis, supporting evidence, explicit approval and largest-remainder rounding. This is a bounded PRJ-02/PRJ-03 increment; M3 remains incomplete.

Scope: active unposted GENERAL sources explicitly classified EXPENSE, with positive saved outflow, a confirmed active unscoped cash Treasury and a source date in the current UTC month. The accountant explicitly confirms that month is open in Company books using the existing scoped allocation/correction-period control. Source dates are preserved, never silently replaced with today. Prior-period split recognition, VAT, supplier/party funding, bank/scoped Treasury, settlement, asset/inventory/advance and Payroll sources are excluded. Ordinary unsplit posting retains its existing behavior. General fiscal closing is not implemented by this increment.

Workflow: select the source's existing Review & Post action; open the current period if required; record reason, basis/support and explicit destinations/weights; preview exact amounts and confirm the plan. This atomically appends an immutable Company/source-scoped versioned event, binds its pointer and resets source review to PENDING. It creates no Expense or journal. The operator must freshly review the source before the existing posting form appears. Changes to source economics/evidence invalidate the plan and require reconfirmation. Reconfirming an unposted plan preserves the previous event. Whole-source assignment cannot silently replace a confirmed shared plan. Posted/reversed sources cannot receive new plans.

Accounting: the existing private Expense engine consumes the authoritative confirmed plan using the stable source idempotency key. It creates one original Expense and one original journal: Dr each Project/overhead cost and Cr the actual Treasury once. No allocation correction journal or second cash event is created. Source amount, plan amounts, Expense net/gross, cash credit and Company expense reconcile exactly. The Expense stores the immutable event reference/plan; its nullable single-Project header is an aggregate header, displayed as Shared allocation rather than overhead. Project remains a journal-line analytic dimension, never a GL account. Stable existing PROJECT_COST/COMPANY_EXPENSE accounts are resolved by key.

Integrity: migration `20261104120000_preposting_shared_cost.sql` adds the immutable source-plan event table and nullable source/Expense provenance fields. Forced RLS, Company-consistent foreign keys, no direct write grants and restricted fixed-search-path commands preserve authority. Confirmation requires the existing Accounting administrator/posting authority. The intended existing function changes are limited to `private.post_expense` and `public.post_historical_expense`; public Expense authority, custody protection, Auth, subscription and reversal functions remain unchanged. The ordinary command hash remains compatible; allocated requests include the immutable plan/event in its hash. The source wrapper checks the exact expected event, including old-client/stale-intent rejection. Company/Project/source locks, request normalization, one root/successor, unique event-to-Expense linkage and canonical financial command reservation protect atomicity, conflicts and replay. Frozen browser transport/storage also retains the expected event ID.

Reversal/correction: the existing explicitly authorized Expense reversal reverses the complete original split journal and retains source/plan lineage. It is not an automatic project-cost correction and must not be used to fabricate a cash return. Existing posted-correction commands safely reject originally split journals outside their supported original-journal shape. Reallocating such posted originals through a cash-neutral correction is the next integration increment; it is not silently enabled here. No posted source, event or financial line is rewritten.

Reports: the Project-cost reader validates each complete allocated original/reversal journal against its plan and real system-account mappings before displaying dimension totals. Source-plan and posted-Expense/ledger Excel/PDF retain Company, source/Expense references, period/date, method/basis/support, driver/units, percentages/quantities, exact amounts, accounting state and audit references. Destination sums are the originating cost, not additional expense. Source review distinguishes unposted/review-required, reviewed/unposted and posted/reversed states. Arabic RTL, English LTR, narrow layouts and all five themes use existing components/styles.
